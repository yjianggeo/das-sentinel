# 站点标定指南

## 为什么不对城市/海底站点声明准确率

模型的泛化高度依赖本地数据分布：城市光缆的噪声谱（交通、施工、管道耦合）与海底
光缆（水声、洋流、缆-岩耦合）彼此差异巨大，也与井下标定数据不同。在没有**本站
人工标注样本**的情况下，任何跨站点准确率数字都是虚构的。因此：

- 平台只在验收报告中给出**真实运行过**的硬件上的性能与合成/真实数据行为；
- 城市（`urban`）与海底（`subsea`）站点在积累足够本地复核样本前，分类输出以
  规则判断为主，模型方法保持弃权（`unknown`），不显示任何准确率承诺。

## 新站点标定流程

1. **建档**：`das-sentinel site add`，显式设置时区与光缆类型
   （`downhole / urban / subsea`）。光缆类型写入处理档案，不可事后静默更改。
2. **小批量试扫**：先拷入数小时代表性数据（覆盖白天/夜晚、已知事件时段），
   `das-sentinel scan <site-id> <path>`。`<path>` 为必填项，必须是站点根目录下的
   具体数据目录（可使用该目录的绝对路径），不能扫描整个根目录。服务端会自动进行
   10 秒稳定性复检，无需再次调用扫描命令；检查完成后检测数量级是否合理。
3. **参数核对**：确认采样率与各频带匹配（Nyquist 必须高于最高分析频带，否则任务
   会以 `invalid_claim` 拒绝）；必要时为该站点新建处理档案版本。
4. **人工复核积累**：在 Web 事件复核页标注。发布门禁要求**每类 ≥ 20 条复核样本、
   验证集 macro-F1 ≥ 0.70 且每类召回 ≥ 0.50**，未达标无法发布模型。
5. **训练与验证**：`das-sentinel train <site-id>`，在模型页查看混淆矩阵与指标；
   候选模型综合分低于当前生产模型时发布会被拒绝（409）。
6. **发布与回滚**：发布需显式确认；异常时 `das-sentinel models rollback <site-id>`
   恢复最近一个退役且过门的模型。

## 几何与命名约定

- 优先读取 HDF5 `SpatialSamplingInterval` 属性；缺失时按 ZD 命名习惯从文件名
  `<...>m_<...>m_` 推断（取最后一个 `Xm` 标记），并在事件证据中标注
  "channel spacing inferred from filename"。
- 注意不同批次命名不完全一致（如 `3400m_4m_2` 中 `2` 可能是抽取因子而非间距），
  标定新批次前用 `das-sentinel benchmark <file>` 抽查一个文件的几何元数据。
- 文件名时间戳与 `RawDataTime` 不一致时会在元数据警告中标记，复核时可见。
