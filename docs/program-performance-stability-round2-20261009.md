## 最小改动及原因

1. 模型扫描列表仍有秒级等待。限定只读生产测量中，十条摘要共 105 条 SQL，服务耗时约 4.265 秒；主要开销在失败任务、最新心跳及近期 ETA 样本查询，而不是 Python 响应组装。这些查询只按现有单列索引查找，过滤/排序需读带大型 `payload_json` 的记录。
2. 新增 `0011_model_scan_summary_index`，仅给任务单元增加 `(scan_id,status,finished_at,kind,started_at,window_count,heartbeat_at)` 覆盖索引，并只 ANALYZE 新索引。扫描领取、运行状态聚合、摘要心跳和样本查询可使用小字段索引；迁移不改业务记录。
3. 摘要的失败单元、失败窗口及 ETA 样本查询只返回实际消费的三个字段，不加载完整 ORM 对象中的任务参数/结果 JSON。WHERE、ORDER BY、LIMIT、错误显示顺序、retryable、四个有效样本门槛、两小时范围及估算公式不变。相同 finished_at 的并列顺序原 SQL 未定义，本轮不引入新排序规则。
4. 阳性窗口补图后的 NPZ 输入只加载一次全部键，供输入 SHA 计算和预测序列化共同使用，六个协议数组从各读两次减为一次，合法额外键保持。
5. 统一距离网格的缓存未命中分支复用已经校验的 waveform、valid mask 和时间数组，输出六个数组保持一致。完整时标、来源/数组 SHA、网格及不可变缓存校验保留。

没有给来源时标或工件 SHA 增加基于 size/mtime 的缓存：现有 fingerprint 不是内容哈希，Windows 源句柄还允许共享写入，仅凭文件 stat 会削弱已有完整性检查。也没有更换绘图算法：合成实验中 pcolorfast 较快，但像素不等；figure 复用的收益有限且涉及生命周期，留作以后单独验证。
