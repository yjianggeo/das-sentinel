# 已扫描数据日历

任务页提供类似 GitHub 贡献图的年度日历，每格代表一个北京时间（UTC+8）采集日期。选择年份和站点查看覆盖情况；默认显示最近有成功扫描记录的年份，无成功记录时显示当前年份。页面可见时每 60 秒刷新一次，隐藏时暂停轮询，也可点击“刷新日历”。

格子按当天去重后的采集覆盖时长着色。这个时长表示已成功处理的数据长度，不是任务运行耗时。

| 每日覆盖时长 | 色阶 |
| --- | --- |
| 0 小时 | 灰色 |
| 大于 0 至 6 小时 | 第 1 档绿色 |
| 大于 6 至 12 小时 | 第 2 档绿色 |
| 大于 12 至 18 小时 | 第 3 档绿色 |
| 大于 18 至 24 小时 | 第 4 档绿色 |

统计以对齐的 30 秒窗口为单位，覆盖以下成功记录：已成功完成的整窗分析、模型成功推理后判为地震或噪声的窗口，以及传统规则已完成检查后因没有合格区域而跳过的窗口。不同模型和分析版本的历史成功记录也计入，即使最新一次分析失败，或所在批次后来被取消。

同一采集时段在多个批次、分析版本或证据来源中出现时只计一次。选择“全部站点”时也按时间并集去重，跨站点重叠时段不会累加，因此每天最多 24 小时。失败、未读取、待处理和仅被排除而没有成功证据的记录不计入。

灰格表示当前保存的记录中没有成功扫描证据，不代表当天没有源数据。已被删除且没有保留成功凭据的历史记录无法追溯。

点击日期可查看已合并的扫描时间区间，相邻 30 秒窗口会合并。区间右端不含，例如 `23:59:30 — 次日 00:00:00` 只覆盖前一天最后 30 秒。

部署时需在项目根目录使用已配置目标本地数据库的环境运行 `python -m alembic upgrade head`，应用包含 `0012` 的统计索引迁移。数据库地址由 `DAS_DATABASE_URL` 或 Alembic 配置提供。
