# DAS Sentinel JJK 目录选择与自动稳定性扫描设计

日期：2026-09-06

## 1. 目标

本次改动解决“扫描 JJK NAS Archive”看似无响应、扫描范围过大和必须手动点击两次的问题：

1. 扫描前由用户选择站点根目录内的一个具体数据目录；
2. 选中目录后递归扫描其全部子目录，不再默认遍历整个 Z 盘映射根目录；
3. 页面持续显示当前扫描阶段、已检查文件数和已发现 H5 文件数；
4. 扫描期间禁用按钮，前后端共同阻止重复扫描；
5. 后端在首次遍历后自动等待稳定期并完成第二次复检；
6. 扫描结束后沿用现有稳定文件校验、来源文件登记、任务去重和入队流程。

扫描始终以只读方式访问 NAS。本次不修改、移动或删除 JJK/HDF5 原始数据。

## 2. 已确认现状与根因

当前站点 `JJK NAS Archive` 的 `data_path` 指向整个
`\\169.254.9.66\Public\`，其当前处理配置开启递归发现。前端向
`POST /api/v1/sites/{site_id}/scan` 发送空请求，然后等待该请求完成；后端则在
请求内同步完成整个目录遍历。因此大目录扫描期间页面没有可见状态，也没有禁用按钮，
用户容易认为程序未响应并重复点击。

`StableFileTracker` 要求同一文件至少经过两次观察，而且文件大小和修改时间在默认
10 秒稳定期内保持不变。当前 Web 页面只调用一次扫描接口，所以首轮通常只建立
观察基线并返回空结果；只有用户稍后再次点击才可能发现稳定文件。CLI 已通过两次请求
和本地等待绕过该限制，但该行为没有封装在服务器端。

## 3. 获批方案与取舍

采用“后台扫描会话 + 页面轮询”方案。创建扫描时，API 立即返回扫描编号；一个
应用内协调器在后台依次执行首次遍历、稳定期倒计时、自动复检和任务入队。页面约每秒
读取一次状态。

扫描状态不写数据库。当前部署使用单个 API 进程，该方案能以最小改动解决长请求、
进度提示和重复扫描问题，同时不引入数据库迁移或新的守护进程。代价是 API 进程重启
会中断正在运行的扫描；页面将把已知扫描编号失效解释为服务重启，并提示用户重新扫描。

不采用以下方案：

- 数据库持久化扫描执行器：可以跨重启恢复，但需要新表、迁移、租约和恢复语义，超出
  当前问题所需范围；
- 复用现有分析任务队列：会把“发现源文件”和“处理已发现文件”混为同一种任务，要求
  大幅修改任务模型和 worker 协议。

## 4. 服务器端目录浏览

新增已认证的只读目录列表接口：

`GET /api/v1/sites/{site_id}/scan-directories?path=<relative_path>`

`path` 是相对于站点 `data_path` 的目录；空值表示站点根目录。响应包含站点名称、
当前相对路径、可用的父路径和当前层的直接子目录。子目录按名称稳定排序，只返回名称和
相对路径，不递归预读，也不列出文件。

目录浏览显示站点根目录内的全部普通真实目录，而不只显示名称以 `jjk` 开头的目录。
符号链接、Windows 重解析点和其他非普通目录不显示且不可选择。后端必须复用或抽取
现有 discovery 路径校验，保证：

- 站点根目录是已存在的绝对目录；
- 相对路径不得包含 `..`，不得是绝对路径；
- 解析后的目录始终位于站点根目录内；
- 从根目录到目标目录的路径链不包含符号链接或重解析点；
- 不在错误响应中暴露未授权的服务器路径。

目录选择器采用逐层浏览，是因为浏览器原生文件夹选择器只能访问用户电脑，不能安全地
代表服务器选择 NAS 路径。前端只提交服务器返回的相对路径，不自行拼接 UNC 绝对路径。

## 5. 扫描接口与状态模型

现有创建接口改为异步语义：

`POST /api/v1/sites/{site_id}/scan`

请求体：

```json
{
  "path": "jjk01/2026-08-31"
}
```

`path` 必须是通过上述目录浏览规则可解析的站点根目录相对路径。页面不提供“扫描整个
站点根目录”的默认按钮；用户必须明确选择目录。为兼容现有 CLI，CLI 可先读取站点信息，
把原有站点根目录内的绝对参数转换为相对路径后再提交。

新扫描返回 HTTP 202 和当前扫描状态。若同一站点已有运行中的扫描，则不创建新会话，
以 HTTP 200 返回现有扫描编号及状态，前端直接接管该会话。

新增状态接口：

- `GET /api/v1/scans/{scan_id}`：读取指定扫描状态；
- `GET /api/v1/sites/{site_id}/active-scan`：读取该站点当前活动扫描；没有活动扫描时
  返回 `null`。

扫描状态包含：

- `id`、`site_id`、选中的相对目录；
- `phase`：`initial_scan`、`stability_wait`、`verification_scan`、
  `enqueueing`、`completed` 或 `failed`；
- 首轮的已检查普通文件数和已发现 `.h5` 候选数；
- 复检的已检查普通文件数和已发现 `.h5` 候选数；
- 已确认稳定且受支持的文件数；
- 已提交到幂等任务创建流程的文件数；
- 未进入任务流程的复检候选数；
- 稳定性复检剩余秒数；
- 面向用户的受控错误信息，成功状态不带错误。

“已检查文件数”统计遍历时实际检查过的普通文件，而不只统计 H5；“发现文件数”只统计
扩展名不区分大小写的 `.h5` 候选。首轮与复检分别计数，不把两次遍历相加。任务提交数
表示稳定文件已交给现有幂等入队流程；已有的相同任务不会被重复创建。

状态保存在应用内存中，每个站点仅保留最近一次会话，避免无界增长。状态读取和更新由
协调器锁保护。阻塞的 NAS 文件系统操作在线程池中运行，稳定倒计时使用异步等待，均不
阻塞 API 事件循环。

## 6. 自动稳定性复检数据流

一次后台扫描会话执行以下确定顺序：

1. 加载启用站点及其唯一当前处理配置，验证用户选择的相对目录；
2. 创建本次会话专用的 `StableFileTracker`；
3. 递归遍历选中目录及全部子目录，逐步更新首轮计数，并让 tracker 记录 H5 快照；
4. 首轮完成后进入 `stability_wait`，按秒更新剩余时间；默认使用 tracker 的
   10 秒稳定期；
5. 自动再次递归遍历同一目录，分别更新复检计数；
6. tracker 仅输出大小和修改时间在稳定期内未变化、探测结果受支持且探测前后未变化的
   文件；第二次遍历中新出现或仍在变化的文件不会入队；
7. 在现有数据库写协调锁内重新验证站点配置和文件快照，并调用现有
   `enqueue_discovered`；
8. 更新最终计数和 `completed` 状态，释放该站点的活动扫描锁。

人工扫描固定为递归处理选中目录，落实已确认的页面行为，不再把整个站点根目录作为
隐式范围。现有分析任务仍绑定扫描时加载的处理配置版本；若配置在发现后发生变化，沿用
现有冲突保护并使扫描失败，不用新配置静默入队。

## 7. 页面交互

任务页中每个站点的原扫描按钮改为“选择目录并扫描”。点击后打开目录选择窗口：

- 顶部显示站点名称、当前位置面包屑和“返回上一级”；
- 主体显示当前层全部可进入的子目录；
- “选择当前目录”记录当前相对路径；
- 页面显示最终选择范围，并由用户点击“开始扫描”；
- 未选择具体子目录时不允许启动扫描。

扫描开始后关闭目录选择窗口，为对应站点显示常驻状态卡片并禁用扫描按钮：

- `initial_scan`：`正在扫描：已检查 1,250 个文件，发现 86 个 H5 数据文件`；
- `stability_wait`：`首次扫描完成。请等待稳定性复检，剩余 8 秒，无需再次点击`；
- `verification_scan`：`正在进行稳定性复检：已复检 64 个文件，确认 58 个稳定文件`；
- `enqueueing`：`正在为稳定文件创建分析任务……`；
- `completed`：显示两轮候选数、稳定文件数、任务提交数和未入队候选数；
- `failed`：显示可操作的中文错误，并恢复“重新扫描”入口。

页面每秒轮询状态；完成或失败后停止。任务页首次加载时查询每个站点的活动扫描，因此
普通页面刷新不会丢失仍在运行的会话。浏览器 `sessionStorage` 记录本页已知的活动扫描
编号；若 API 重启后该编号不存在，页面显示“扫描因服务重启而中断，请重新扫描”。扫描
完成后自动刷新任务列表。

按钮禁用只作用于正在扫描的站点；不同站点可以分别启动扫描。后端仍是重复扫描保护的
最终权威，不能只依赖页面状态。

## 8. 错误处理

- 站点不存在返回 404；站点禁用、处理配置无效或扫描后配置改变返回 409；
- 空路径、根目录选择、路径越界、目录不存在、符号链接或重解析点返回 422；
- NAS 断开、目录无读取权限或遍历过程中无法继续时，会话进入 `failed`，对用户显示
  不泄露内部绝对路径的中文错误，服务端日志保留诊断细节；
- 单个 H5 损坏、不受支持、探测时变化或稳定期内发生变化时，该文件不入队，其他文件
  继续处理；最终以“未入队候选数”呈现，不把整次扫描标为失败；
- 目录中没有 H5 时正常完成并显示“未发现可处理的 H5 数据文件”；
- 后台任务无论成功、失败或取消都在 `finally` 中释放站点活动锁，避免按钮永久不可用；
- API 服务重启不尝试恢复半完成的内存会话，用户重新扫描即可安全重建快照基线。

## 9. CLI 兼容

`das-sentinel scan` 改为只创建一次服务器端扫描会话并轮询到终态，打印与页面一致的阶段
和计数，不再自行等待并发送第二次请求。现有 `settle_seconds` 客户端选项删除，稳定期由
服务器 tracker 统一控制。

CLI 路径参数改为必填，允许使用站点根目录内的绝对路径或非空相对路径；CLI 在提交前
把绝对参数转换为服务器接口使用的相对路径，并拒绝站点根目录本身。这一处有意收紧旧
CLI 的省略路径行为，避免任何入口再次无意扫描整个站点根目录。`watch` 增加同样的必填
路径参数，并改为等待每个自动扫描会话结束后再按原间隔启动下一轮，不能与已有活动扫描
重叠。

## 10. 测试与验收

后端单元与 API 测试覆盖：

- 目录列表只返回当前层真实子目录，排序稳定，Unicode 名称可用；
- 空相对路径浏览根目录，`..`、绝对路径、越界目标、符号链接和重解析点被拒绝；
- 创建扫描立即返回 202，API 在大型遍历期间仍可响应状态请求；
- 首轮计数、稳定倒计时、复检计数和终态按顺序变化；
- 使用可控时钟/等待替身证明一次请求会自动完成两次观察；
- 变化、新出现、损坏和不受支持的文件不入队，稳定支持文件只入队一次；
- 同一站点重复请求返回同一扫描编号，不执行第二次目录遍历；
- 不同站点可以拥有独立会话；
- 空目录正常完成，NAS 遍历异常进入失败状态，所有终态释放活动锁；
- 处理配置变化继续触发现有冲突保护；
- 现有任务幂等性保持不变。

前端测试覆盖：

- 打开目录选择器、逐层进入目录、返回上级和选择当前目录；
- 未选择具体子目录不能扫描；
- 扫描请求只发送服务器返回的相对路径；
- 扫描期间按钮禁用，重复点击不发送第二个请求；
- 六种阶段显示正确中文提示和对应计数；
- 轮询终态后停止并刷新任务列表；
- 页面刷新后接管现有活动扫描；
- 已知扫描在服务重启后失效时显示中断提示；
- 空目录、目录访问失败和普通 API 失败显示可操作信息。

实现后依次运行：

1. 新增的 discovery、扫描协调器和扫描 API 聚焦测试；
2. 后端完整 pytest；
3. 前端完整 Vitest、TypeScript 检查和生产构建；
4. 在本机服务中选择一个明确的 `jjk*` 子目录执行只读验收，确认页面计数、自动复检、
   按钮禁用和任务刷新；
5. 验收前后核对目标 NAS 目录内容未发生变化。

基线为后端 750 项通过、4 项跳过、1 项性能测试未选，以及前端 58 项全部通过。

## 11. 非目标

本次不增加扫描取消按钮，不把扫描历史写入数据库，不支持一次选择多个目录，不支持
任意服务器文件系统浏览，不改变事件检测、分类、GPU 加速、NAS 原始数据格式、任务
worker 或现有分析结果。依赖审计中已有的版本风险不在本次功能范围内，不进行顺带升级。
