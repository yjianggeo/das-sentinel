# JJK 时间语义与事件图件显示修复设计

## 目标

修复 JJK ZD/PRODML HDF5 数据的时间解释，使文件名 `UTC8_YYYYMMDDHHMM` 表示的站点本地时间被规范化为 UTC 存储，并在事件界面、图件和时间特征中按站点时区显示。同时修复导出 PNG 内容贴边及全屏关闭按钮遮挡图像的问题。

验收结果为：样例 `UTC8_202405271528` 在内部表示为 `2024-05-27 07:28 UTC`，在 `Asia/Shanghai` 站点显示为北京时间 `2024-05-27 15:28`；所有图件标题、坐标轴和图像内容完整可见，全屏按钮不覆盖图像。

## 时间处理

ZD HDF5 读取器识别文件名中的 `UTC<offset>_<timestamp>`。只有当文件名墙钟时间与首个 `RawDataTime` 解码后的年月日时分相符时，才将该偏移应用到整个数据文件。这样可修正把本地墙钟写入 epoch 数值的 JJK 文件，同时不影响文件名不含该标记或已经使用真实 UTC 时间的文件。

读取器输出仍遵守现有领域约定：所有 `start_time_utc` 均为带时区的 UTC 时间。事件 API 在摘要与详情中增加站点 IANA 时区。前端使用事件携带的时区格式化 `occurred_at`，不依赖浏览器所在地，也不硬编码北京时间。

事件特征提取继续接收 UTC 时刻，同时从管线上下文获取站点时区；`time_of_day_hours` 按站点当地时间计算，保证时间相关分类特征与界面一致。

## 图件导出与全屏布局

Matplotlib PNG 导出统一使用紧边界和少量留白，确保标题、顶部本地时间轴、底部 UTC 时间轴及标签不会被画布边缘裁切。

全屏查看器维持现有 DOM 和交互语义，只调整布局：遮罩层提供安全内边距和必要时滚动；对话框分为按钮行和图像行；关闭按钮使用普通布局放在图像上方；图像采用 `object-fit: contain` 并限制在剩余视口高度内。因此按钮和图片边界不会相交，图片上下边缘均保留在可视区域内。

## 兼容性与数据修复

不更改普通 HDF5、无 `UTC<offset>` 标记文件或文件名时间与数据时间不一致文件的现有解释。站点时区沿用现有 `Site.timezone` 配置。

代码验证通过后，先备份当前应用数据库及该验证事件图件，再只清理并重新处理本次生成的 JJK 验证任务、事件和图件，使现有页面采用新语义。不会删除站点、管理员或其他数据。

## 测试

- 读取器单元测试：证明 `UTC8` 样例由本地墙钟转换为 UTC，并证明普通 UTC 文件保持不变。
- 特征单元测试：证明 UTC 事件时刻按站点时区计算当地小时。
- API 测试：证明事件摘要和详情返回正确的站点时区。
- 前端测试：证明 UTC 时刻按事件站点时区显示。
- 图件测试：检查生成 PNG 四周存在可见留白，避免内容触边。
- 浏览器布局测试：检查全屏按钮与图片边界不相交，图片完整处于视口内。
- 回归验证：运行相关后端测试、前端测试和生产构建，并用当前 JJK 文件重新处理后在浏览器复验北京时间 `15:28` 与完整图件。

## 非目标

本次不修改事件检测和分类阈值，不重构图件组件，不改变其他数据格式的时间约定，也不引入新的时区配置项。
