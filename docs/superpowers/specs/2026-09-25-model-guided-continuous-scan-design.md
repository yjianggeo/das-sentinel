## 方案选择

推荐：先对所有有效30秒窗口直接推理，模型阳性才进入完整复核加工流程。传统检测仅为阳性窗口补充疑似区域，不作为进入模型或保留阳性窗口的门槛。

保留旧的“传统检测通过后才模型判断”改动较小，但会继续漏掉前置规则未触发的信号，不满足这次直接扫描的目标。逐窗运行完整旧流程再隐藏模型阴性可以获得类似列表，却保留了大量读取、测量、压缩和绘图开销，不适合当前大量剩余数据。

## 固定模型与输入契约

1. 每个扫描批次冻结上述模型ID、权重/元数据SHA、阈值和输入协议。批次运行中即使站点以后切换模型，当前批次也不悄悄换权重。
2. 30秒UTC半分钟对齐，100 Hz、每道3000点；输入为带抗混叠降采样的原始波形，不能改成0.5–40 Hz滤波图像或抽点替代降采样。
3. 使用权威HDF5物理距离元数据和既有834道统一网格。缺失尾道保持无效掩码；≥300 m裁剪后760道，裁剪之后才按原算法归一化。region_id仍表示悬空/地表/井中物理分区。
4. 保留真实上下文、时钟单调性、接缝、单位、网格和源文件稳定性检查。不通过的窗口记为无法判定/失败，不记为噪声，不补零伪造连续信号。
5. 当前地震类包含爆破，噪声类包含车辆；人工确认才生成训练标签。

## 处理流程与提速

`限定目录发现 → 来源与覆盖检查 → 有界连续读取/100 Hz降采样 → 按30秒切窗 → 常驻模型判断 → 阳性图件与复核队列`

- 目录发现按目录逐步登记，记录发现进度；使用稳定性复检。不会先创建数百万个旧式整窗事件与图件任务。
- 按连续时间段读取，复用相邻窗口重复的源时钟验证、文件访问和下采样数据。保持输出缓冲低于现有256 MiB限制，初始核心块不超过5分钟；预取队列最多一个块，缓存有大小上限。
- 分块时保持既有抗混叠保护区和UTC采样相位。与旧逐窗读取做数值对照后才能采用；若边界不一致，先保留原读取路径，仅启用已验证的常驻推理和阳性出图优化。
- 一个常驻Torch子进程加载一次冻结模型，以现有CPU双线程、单窗推理为起点；HDF5读取进程通过有界临时数组协议提交输入。没有测量依据前不增加多路NAS读取或大量worker。
- 模型阴性只保存轻量扫描回执：模型/输入身份、分数、阈值和完成状态，不保存每窗训练数组或图件、不进入日常复核队列、不生成“人工噪声”标签。
- 模型阳性先持久登记入选身份，再生成现有30秒原始/滤波全通道图件和复核所需数据。即使没有合格STA/LTA局部区域也保留。已有成功图件优先复用。
- 阳性图件默认仍覆盖全通道，包括300 m之前；模型判断范围仍是300 m之后。
- 阳性加工复用当前完整分析和图件契约，避免破坏已有标签与训练接口。新快路径的模型输入必须与最终保存的复核输入校验一致，才能绑定、展示同一条预测；不把旧输入的预测直接挂到新分析上。
- 一致性校验覆盖未滤波834×3000波形、距离、有效/识别掩码、来源身份及裁剪前后协议。数值容差通过对照试验固定；阈值附近同时用原路径输入复算，不能有未解释的分类差异。不一致时保留“已入选／输入不一致待处理”，不发布到模型推荐，也不把先前分数绑定到新分析；修复并复核一致性后才能完成发布。

## 持久任务、去重和保护

- 独立模型扫描模式，保存批次、来源清单、连续块进度以及逐窗判断回执；任务页能查看运行/暂停/失败/完成，并支持暂停、继续与失败重试。
- 去重绑定站点、UTC起点/时长、来源与输入协议身份、模型权重及阈值策略。相同批次重启或重复提交不产生重复事件；不同模型或已改变来源不能误用旧完成记录。
- 文件名、目录名或mtime相同不构成信号内容相同的充分证据。时间重叠时复用现有源检查；仅在确认内容相同后合并副本，冲突数据单列。
- 已有有效人工复核窗口不重新生成或覆盖，也不更新其 `latest_analysis_id`、人工标签或输入绑定。现有成功分析先检查可复用输入、图件及该模型的已完成判断，避免重读NAS；不能因重复入队使既有人工标签失效。
- 610条规则跳过记录保留原义，由新模型扫描回执独立记录补扫结果。不能把它们直接当作本轮已扫描或删除去重历史。模型阳性使用明确的模型入选加工路径，不调用会按旧 `empty-regions-v1` 回执抑制入队的普通路径，也不启用无局部区域即删除的规则；仍须执行人工窗口保护和阳性入队去重。
- 从 `D:/das-sentinel-runtime/manual-work/window-incomplete-removal-20260925/deleted-records.json` 固定431个排除身份。遇到明确取消的现有任务也不自动恢复。
- 原始文件、已有图件、人工标签、当前在线模型不删除或批量改写。模型阳性加工失败时保留“已入选/待补图”状态，不丢失发现结果；异常不得计入阴性完成数。
- 任务领取、回执与阳性入队需要原子事务和所有权校验。崩溃恢复只补做未完成阶段，正常取消不自动续跑。
- 目录完成标记与完整枚举、稳定性复检后的来源清单一起提交；未完成枚举的目录恢复后继续核对。块游标只能在该块所有窗口已持久记录结果或明确排除原因后推进，恢复时用计划与回执核对缺项，不能仅凭内存游标跳过尚未提交的文件或窗口。

## 人工复核与任务显示

- 事件复核增加“模型推荐”范围，仅展示该扫描模式入选且完成有效复核数据的窗口，默认待复核，按模型得分降序、时间和ID稳定排序。与传统规则分数分别标明。
- 不把模型阳性写成传统规则 `candidate=true`：当前“传统规则证据”文字及原筛选条件保留真实含义。没有局部区域的模型阳性也可以打开整窗图并人工标注。
- 队列显示“模型推荐”、模型版本和得分；得分不写成地震概率。继续使用现有地震/噪声/待确定标签与输入版本绑定。
- 任务页显示目录发现阶段、已判断窗口数、模型入选数、模型阴性数、无法判断数、待补图数和已生成复核窗口数。输入范围枚举未完成前不宣称精确总量。
- 用实际扫描速度动态估算剩余时长和结束时刻；扫描与阳性图件阶段分别计时，避免模型判断已完而图件未完时显示全部完成。

3. 选取短连续数据和已有正负窗口，对照原读取及模型路径。检查时间/距离/掩码精确一致、数组误差与模型得分误差，尤其阈值附近窗口；必须无未解释的分类差异。模型阈值固定，不根据试扫结果偷偷调参。
4. 在相同源文件、窗口、线程和缓存条件下计时，分别记录目录/源检查、NAS读取/重采样、推理、绘图/写盘及端到端耗时。报告内存峰值和缓存占用。只有实测吞吐改善的快路径进入批量扫描，不预先承诺倍速。
5. 先跑覆盖不同文件布局和新日期的小批次，核对“模型推荐”可见、图件完整及阴性抽查。当前模型原先主要在候选窗上训练，连续背景的误报率需另测，历史测试成绩不能当作整盘扫描成绩。
6. 试扫通过后按目录逐批推进12个JJK目录及规则跳过记录。对不兼容文件记录原因并继续其余数据；不以错误窗口制造地震/噪声标签，不一次性将全部NAS文件复制到本地。
