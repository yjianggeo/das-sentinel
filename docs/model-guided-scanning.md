# 模型直接扫描

模型扫描以 UTC 每分钟 00/30 秒对齐的 30 秒窗口为单位，覆盖指定 JJK 目录的未处理数据及传统规则跳过窗口。它与历史文件扫描、普通整窗图件任务分别保存和控制。

创建批次时冻结站点处理配置、当前部署模型、权重/元数据摘要、阈值和删除排除清单。本次使用部署 `80681390-1d01-492a-8be5-306c6636220d`，阈值 `0.03820184990763664`，不会因随后切换站点模型而改变此批判定。

## 处理与复核

1. 分页发现来源，以 HDF5 内部时间为准。登记过的文件（包括 eq）只补充上下文；不会递归发现 eq 或扩大请求日期。
2. 来源清单完成后，每次最多规划 5 分钟，逐窗保存持久回执。校验真实上下文、采样时标、单位、距离网格及源稳定性，无法读取或拼接的窗口记为无法判断。
3. 100 Hz 抗混叠降采样的未滤波数据统一为 834 道，模型裁剪 ≥300 m 的 760 道，之后按部署协议归一化。常驻 CPU Torch 进程加载一次模型。
4. 阴性仅保存轻量回执，不生成图件、训练数组、事件或人工噪声标签。阳性先登记入选，再生成全通道原始/滤波瀑布图；无局部疑似区域也保留。最终模型输入和初筛输入 SHA 必须完全一致，冻结模型复算得分也须一致且仍达阈值。
5. 在任务页“模型扫描”查看进度、暂停、继续及失败重试；在事件复核“模型推荐”查看已完成图件的入选窗，默认待复核、按模型得分降序。模型得分不是校准概率，类别由人工决定。

人工复核窗口（含待确定记录）保持原标签和分析绑定。431 个明确删除窗口固定排除，已取消的分析及历史文件任务不会自动恢复。旧规则 skip 回执保留。相同批次的重启不重复入选；跨批次仅复用来源/输入协议/冻结模型身份一致的新扫描回执。

## 速度和资源

`--read-mode single` 是逐窗读取基线。`--read-mode block` 在一个最多 5 分钟的工作单元内共享 64 MiB LRU 缓存，复用既有 20 秒重采样片段，保持原 UTC 分块相位、10 秒抗混叠边界和全部时标/源身份检查。缓存不跨来源变化使用，不预取多个大块，不同时启动多个 NAS 读取 worker。

目录发现复用当前算法版本的源元数据缓存，跨批次避免重复解析同一文件。命中仍检查路径、文件身份和前后快照；损坏或不完整缓存重新读取，旧版本缓存不混用。本机回环 API 连接跳过系统代理发现，远程 API 保留原代理行为。

2026-09-25 真实四段、40 窗对照：36 窗可读，4 窗缺上下文，两种模式的六数组、输入 SHA、得分和错误结果一致。读取加推理合计 243.068 秒与 208.216 秒，吞吐从 8.886 增至 10.374 窗/分钟；逻辑读取字节减少 16.30%。这是受控样本，不包含目录发现和阳性补图，不能作为全盘完成时间承诺。首次/暖读取由操作报告注明，没有清空 Windows/NAS 缓存。

另对已标一正一负完整回放，模型初筛约 10 秒/窗，旧完整分析约 76 秒/窗；输入与得分完全一致。阳性仍承担补图成本，实际收益取决于连续数据中的入选比例。

来源枚举未完成时不显示精确总数或 ETA。完成枚举后，分别根据近期至少四个推理/加工样本的墙钟耗时估算；估算包含已入选待出图及观察到的入选比例。暂停、等待 worker 或样本不足时显示状态，不显示虚假的 0 秒。

## 运行与恢复

API 新增 `/api/v1/sites/{site_id}/model-scans`、`/model-scans`、`/model-scans/{id}` 和 `/{pause|resume|cancel|retry}`。读取使用管理员会话，创建/控制需要 CSRF；内部工作接口沿用 worker token。worker 经 API 短事务提交，不直接写生产库。

启动：`python -m das_sentinel.worker.model_scan_main --worker-id model-scan-1 --read-mode block`。使用既有 `DAS_*` 环境配置，`DAS_INFERENCE_PYTHON` 指向 Torch 环境。后台窗口隐藏，日志与 PID 保存在 `D:/das-sentinel-runtime/manual-work/model-guided-scan-20260925`。

暂停停止新的领取，当前工作单元允许完成；取消拒绝迟到结果且不能恢复。过期租约在重新领取时换用单调递增代次，显式重试也不会复用旧代次。推理失败可重试未成功窗，已选中但补图失败则仅重试加工。文件缺失、变更或格式不兼容需要修复后新建批次，重新发现来源。页面显示首批来源和窗口错误详情。

限制：旧普通模型预测缓存尚未用于新模式的免读取复用，已有未复核样本可能再读一次；中断期间移走子目录，旧发现单元可能失败，需新建批次。静态档案应在扫描期间保持目录结构稳定。

2026-09-27 按用户要求，2023 年已发现的 1663 道、2.044989824295044 m 间距数据退出模型扫描范围。按文件元数据中的实际时间和距离坐标匹配，不按目录名一概排除：当前共 358 个唯一文件，其中 `jjk2023` 下 307 个、`jjk20230919/20230926` 下 51 个；其余 7144 个正常网格的 2023 年文件保留。

规划时保留轻量“已排除”回执供进度和去重使用，不再读取这类来源的波形、计算整文件哈希、推理或生成图件，也不生成噪声标签。同一时间若有正常来源，则仅使用正常来源规划；缺少正常上下文仍如实记录无法判断。已有人工复核优先保护。排除回执使用 `excluded_2023_two_metre` 原因，失败重试不重开它们。模型输入网格及权重保持不变，其他不兼容几何仍走原有校验。

## 2026-10-12 读取重叠边界优化

100 Hz 连续读取现在在一次调用内保留前一段原始数据，按源文件和绝对采样编号复用相邻 20 秒核心的重叠边界。仅当所选通道能放入一个既有 IO 组时启用，额外保留的数据最多 128 MiB，调用结束即释放；5 Hz 和多个 IO 组仍走原读取路径。既有 64 MiB CoreCache 保持不变，没有跨调用的原始数据缓存。

10 秒抗混叠边界、UTC 分块相位、重叠文件的后文件归属、完整时标检查、非有限值检查和来源身份检查均保持原样。模型、阈值及输入协议不变。来源身份仍沿用静态档案的路径、大小、mtime 合同，不增加同大小且恢复 mtime 的内容复写检测保证。

## 2026-10-12 全流程性能审查后的三项优化

本轮沿用上一轮已上线的原始边界缓存，优化任务状态提交、重采样和来源检查，不改变模型、阈值、识别距离、采样率或图件内容。

扫描提交结果时，原 `_refresh` 会先汇总整个批次的工作单元，再判断是否仍有排队或运行任务。现改为在同一写事务内用覆盖索引查询是否存在活动单元，找到一个即返回；暂停、取消及无活动任务时的终态汇总、失败优先级和来源错误处理保持原样。真实单批次的 ABBA 只读对照中，原查询每次逻辑读取约 688 MB、耗时 0.588/0.727 秒；存在性查询约 12 KiB/0 字节、耗时 0.000061/0.000010 秒。这是查询阶段证据，不等同于全盘扫描提速倍数。

连续读取的插值临时数组改为按列连续的 Fortran 布局，减少逐道插值和重采样的内存开销。形状、float32、插值顺序、抗混叠 FIR、多相重采样、UTC 相位、保护区及缓存上限不变。单次来源检查增加 `read_metadata_and_count`，在一个新的 HDF5 句柄内同时取得元数据和样本数；读前、读后检查、完整时标检查和有限值检查保留，没有跨调用的元数据或时钟缓存。
