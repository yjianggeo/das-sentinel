# 性能与复核界面优化（2026-10-10）

本轮在现有 `fix/jjk-scan-progress` 工作目录上实施，保留此前所有未提交修改。目标是减少当前 30 秒复核流程的计算和界面冗余，保持模型、阈值、检测结果和训练输入协议。

## 已实现范围

- 移除“更多测量参数”，新分析只计算四项用于复核的整窗摘要：有效通道比例、活动通道比例、连续活动距离、相邻通道时移相关性。已有保存结果不重写；井下广覆盖、传播与共模残余评估继续独立计算、显示。
- 人工标签紧接图件；局部区域列表默认收起，展开后才加载局部预览。规则证据分数显示四位有效数字，模型得分和阈值保留原格式。
- 新整窗 PNG 不烧录区域框，开关使用浏览器叠加框，不重新读取训练数组或绘图。API 的整图预览校验输入图件摘要后复用 PNG；旧图件缺少新标志时沿用兼容路径。图像网格、颜色与滤波数组不变。
- 轨迹搜索按最多 256 个起点分块向量化，保持原求和顺序、最早同分起点和检测证据。模型数组摘要使用连续缓冲区，图件摘要流式计算，减少全文件及数组字节复制。
- 删除没有调用方的旧前端训练准备/验证组件、局部事件队列主体、相关类型和专属样式。共享时间格式、低频接口和后台/迁移/CLI 的必要依赖保留。
- 运行总览使用当前 30 秒窗口最新分析、模型扫描批次和输入绑定的最新人工二分类标签，不统计历史局部事件或历史文件任务。未知和过期标签列为待复核，不能解释为噪声或可训练数据。

## 受控性能对照

对比基准是本轮实施前的源码快照，不是 Git HEAD；Windows 单 CPU 亲和性、NumPy/BLAS 单线程，暖运行后取中位数。没有清空系统或 NAS 缓存。

| 测量范围 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 轨迹单条线路搜索，3000 × 64，5 次 | 19.34 ms | 0.81 ms |
| 整窗摘要，本地真实 3000 × 832 波形，拼接 90 秒背景，3 次 | 0.957 s | 0.202 s |
| 六数组摘要，128 × 3000 float32，5 次 | 1.17 ms | 0.81 ms |
| 数组摘要峰值临时分配（tracemalloc） | 1.54 MB | 1.17 KB |
| 真实数据库总览统计查询，两部分合计 | 8.846 s | 0.063 s |

保留的四项摘要与旧函数精确相同；轨迹独立审查的 168 个边界/数值案例、实际缓存子集 5 个非空候选完整字典，以及 27 个摘要布局/端序案例均保持一致。新原始和滤波 PNG 与旧无标框参考图字节一致，改变的像素仅为旧区域框及编号。

总览统计改为先物化分析记录的窄投影，读取既有覆盖索引，避免读取大型结果 JSON；真实数据库前后状态及标签统计精确相同，没有增加索引或改变数据库结构。上线后的首次认证总览请求为 0.070 秒。

以上是单个计算环节的结果，不能按相同比例推算整盘扫描速度。NAS 读取、降采样、局部检测、压缩、绘图及共模评估仍需要时间；以前记录的加工单元 finished_at 也早于 HTTP 中的共模评估结束，不代表完整请求耗时。
