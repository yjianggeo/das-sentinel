- 确认备份磁盘空间足够。备份放入本次独立目录，不能覆盖现有备份。

## 排空与上线

1. 通过既有 CSRF API，仅对检查时为 queued/running 的模型扫描批次调用 `pause`，逐项记录成功结果。既有 paused/cancelled 批次保持原状态，不调用 cancel/retry。
2. 现有 pause 只禁止新领取，当前工作单元仍可心跳和完成。等待全部正在运行单元结束，同时观察 worker 和心跳；不杀掉正在读取的工作单元。若无法正常排空，停止后续步骤并报告具体状态。
3. 排空后确认没有其他后台写入者，再停止已核对的那个 worker 进程树与本地 API；不按模糊进程名批量终止。
4. 使用 SQLite 一致备份接口创建生产库备份，记录迁移前标签、收藏、窗口输入绑定摘要以及模型指针哈希。备份成功且可读才继续。
5. 使用既有 `upgrade_database` 执行到 0010。迁移事务与全外键检查必须成功，不绕过检查；比较迁移前后记录摘要、模型指针、批次状态和查询结果。迁移失败时保持备份和日志，停止正常上线流程，不强制重置记录。
6. 使用已核对的 `start-api-only.ps1` 隐藏启动 API，检查 `/healthz`、登录会话、代表性列表/详情请求。
7. 仅恢复本次维护成功暂停的批次，再使用原 `start-model-worker.ps1` 隐藏启动一个 `model-scan-1`、block 模式 worker。启动前确认无残留 worker；取消任务不恢复。
8. 验证新 worker 命令、心跳和真实任务推进，核对模型指针与标签/收藏未被维护改写；保存完整上线证据。

## 恢复策略

建索引为增量迁移，不删除业务记录。迁移失败由现有事务回滚；恢复 API 前先核对实际 schema，不盲目执行降级。旧前端入口及旧哈希资源已经单独保留。若需要回退后端代码，按本轮 `before` 快照恢复本轮改动，不使用 `git reset` 或覆盖用户原有脏态；先在副本验证后再执行。

维护窗口长度取决于当前工作单元结束时间、生产磁盘备份和外键检查，不能提前保证固定秒数。权限只覆盖上述暂停、备份、迁移和单 worker 恢复，不扩大为数据删除、模型训练或 GitHub 发布。
